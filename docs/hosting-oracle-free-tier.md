# Хостинг демо на Oracle Cloud Always Free

Статус: черновик инструкции, пользователь пробует этот вариант (2026-09-11).

Oracle Cloud "Always Free" даёт бесплатно навсегда (не триал) ARM-инстансы
(shape `VM.Standard.A1.Flex`), плюс до 200 GB диска и постоянный публичный
IP. Этого достаточно, чтобы держать один VPS под несколько docker-compose
проектов за общим reverse-proxy.

⚠️ **Обновление (2026-09-12)**: Oracle тихо (без анонса) урезал Always
Free лимит Ampere A1 вдвое — с 4 OCPU/24 GB до **2 OCPU/12 GB**, изменение
вступило в силу 15 июня 2026. С 18 августа 2026 существующие инстансы
сверх нового лимита начали удалять. Т.е. сейчас для нового аккаунта
доступно максимум 2 OCPU/12 GB (одним инстансом или разбить на несколько
мельче) — это меньше, чем закладывали в §5.1 design.md изначально, но всё
ещё достаточно для демо. Планировать ресурсы под 2 OCPU/12 GB.

## 1. Регистрация

1. https://signup.oraclecloud.com — завести аккаунт (Free Tier). Нужна
   карта для верификации личности, но списаний не будет, пока сам не
   перейдёшь на платный тариф (Oracle прямо спрашивает подтверждение перед
   апгрейдом).
2. Выбери домашний регион (home region) ближе к тебе/пользователям — учти,
   что Always Free ресурсы доступны **только в домашнем регионе**, сменить
   его потом нельзя без пересоздания аккаунта.

## 2. Сеть — создать ДО инстанса (иначе quick-create урежет варианты)

Консоль Oracle сама предупреждает: inline-создание VCN/subnet прямо в
форме "Create Instance" даёт урезанный набор опций (в частности, не даёт
явно выбрать Public/Private subnet). Поэтому делаем сеть отдельно, заранее:

1. Левое меню → **Networking** → **Virtual Cloud Networks** → **Start VCN
   Wizard** → **"Create VCN with Internet Connectivity"**. Это создаёт
   сразу правильно: VCN + публичный сабнет + приватный сабнет + Internet
   Gateway + маршрутизацию — без ручной возни.
   (Вариант вручную: Create VCN → отдельно Create Subnet → в форме явно
   выбрать **Subnet Access → Public Subnet**.)
2. При создании инстанса (см. ниже) в Networking выбрать **"Select
   existing virtual cloud network"** и указать эту сеть и её публичный
   сабнет — тогда галочка "Assign a public IPv4 address" будет доступна
   и включаема нормально.

Если инстанс уже создан с неправильной (приватной) сетью — можно просто
**Terminate** его (бесплатно, без потерь, пока ничего не задеплоено) и
пересоздать заново, указав уже готовую сеть с шага 1. Пересоздание
инстанса на этом этапе ничего не стоит.

## 3. Создание инстанса

1. Compute → Instances → Create Instance.
2. Image: **последний Ubuntu LTS** из списка (на 2026-09 это Ubuntu 26.04;
   если увидишь более новый LTS — бери его, старые версии тут указывать
   не стоит) — с Ubuntu меньше сюрпризов для Docker, чем с Oracle Linux.
   Консоль сама показывает только образы, совместимые с выбранным
   ARM-шейпом (A1.Flex), так что если версия в списке — она подходит.
3. Shape: **Ampere (ARM), VM.Standard.A1.Flex**. Бери **2 OCPU / 12 GB**
   одним инстансом — это весь нынешний Always Free лимит (см. обновление
   выше), делить на несколько мельче инстансов сейчас смысла меньше.
   ⚠️ Известная проблема: Always Free A1-инстансы физически может не
   хватать в регионе ("Out of capacity") — если отказ, пробуй другую
   Availability Domain или создавай в другое время суток, это временное
   ограничение мощности, а не отказ аккаунта.
4. **Capacity type** (Advanced options → Placement): выбирай
   **On-demand capacity** (это дефолт и единственный вариант, совместимый
   с обычным Always Free использованием). Остальные варианты не подходят:
   *Preemptible* — дешевле, но Oracle может забрать инстанс в любой
   момент, не для постоянного сервера; *Capacity reservation* — требует
   заранее созданную резервацию, лишняя сущность для демо; *Dedicated
   host* — отдельный физический хост, точно платно, не Always Free;
   *Compute cluster* — для HPC/RDMA, не актуально. Уменьшение лимитов,
   о котором речь выше, не связано с выбором capacity type — это
   отдельное урезание тарифа Oracle, а не следствие выбора "on-demand".
4. Networking: выбери **"Select existing virtual cloud network"** и
   укажи VCN + публичный сабнет, созданные в §2 — "Assign a public IPv4
   address" включится сама/станет доступна для включения. ("Primary
   VNIC" в форме — это просто название сетевой карты инстанса, отдельно
   настраивать её не нужно, всё дело в выборе subnet.)
5. SSH keys: сгенерируй пару (`ssh-keygen -t ed25519`) и вставь публичный
   ключ, либо загрузи существующий. Приватный ключ сохрани локально.
6. Create.

## 4. Сеть — Security List / NSG (порты)

По умолчанию открыт только порт 22. Добавь Ingress Rules для публичной
подсети (VCN → Security Lists, или отдельная Network Security Group):

- TCP 80 (HTTP) — 0.0.0.0/0
- TCP 443 (HTTPS) — 0.0.0.0/0
- TCP 22 (SSH) — уже есть, по желанию сузь до своего IP

Плюс на самой Ubuntu-машине включён `iptables`/`netfilter` от Oracle —
после установки Docker его правила иногда конфликтуют с
docker-managed iptables; если контейнер слушает порт, а снаружи не
достучаться — проверить `sudo iptables -L` и `ufw status` на инстансе, не
только облачный Security List.

## 5. Подключение и базовая настройка

```bash
ssh -i ~/.ssh/<приватный_ключ> ubuntu@<PUBLIC_IP>

sudo apt update && sudo apt upgrade -y

# Docker + Compose plugin (официальный скрипт)
curl -fsSL https://get.docker.com | sudo sh
sudo usermod -aG docker $USER
# перелогиниться, чтобы группа применилась

docker compose version   # проверка
```

## 6. Reverse proxy для нескольких проектов

Ставим один Caddy (или Traefik) на весь сервер, каждый проект — свой
docker-compose стек на внутреннем порту, Caddy маршрутизирует по
поддоменам и сам получает TLS-сертификаты (Let's Encrypt) автоматически:

```caddyfile
# /etc/caddy/Caddyfile (пример)
store-service-demo.example.com {
    reverse_proxy localhost:8080
}

other-project.example.com {
    reverse_proxy localhost:8081
}
```

Домен нужен свой (или поддомен на уже имеющемся) — A-запись на публичный
IP инстанса.

## 7. Что такое k3s (раз уж спросили)

Kubernetes — система оркестрации контейнеров: сама решает, на какой
машине запустить контейнер, перезапускает упавшие, балансирует нагрузку
между репликами, раскатывает обновления без даунтайма. Полноценный
Kubernetes (k8s) — тяжёлая штука, обычно нужен кластер из нескольких
машин и заметный оверхед на управление.

**k3s** — облегчённый дистрибутив Kubernetes (от Rancher), тот же API и
концепции, но с упрощённой раскладкой и меньшим потреблением ресурсов —
ставится одной командой и нормально работает даже на одной небольшой
VPS. Это осмысленный следующий шаг, когда: контейнеров/проектов на
сервере станет много и их вручную через docker-compose становится
неудобно поднимать/обновлять, либо когда понадобится несколько серверов
и балансировка между ними. Пока (один демо-проект, один сервер) — не
нужен, docker-compose + Caddy достаточно. Мы сможем перейти на k3s на той
же машине позже без смены архитектуры контейнеров — это и была идея
рекомендации в §5.1 design.md.
