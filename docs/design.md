# store-service — дизайн-документ

Статус: черновик v0.1 (кикофф), обсуждается с пользователем.
Ведётся здесь, чтобы подхватывать из любой сессии/машины.

## 1. Идея продукта

Сервис для небольших магазинов (ткани в метрах, пиво, одежда и т.д.):

- **Покупатель** (сайт + мобильное приложение): смотрит товары с остатками,
  резервирует товар, может отменить/вернуть резерв. Оплаты пока нет.
- **Администратор**: добавляет товары (фото/видео), редактирует остатки,
  подтверждает выкуп резерва (резерв → продажа, остаток списывается).

Это демо: сначала обкатываем на знакомых, дорабатываем, потом выводим на рынок.
Предполагается, что "коробку" в будущем будут клонировать и дорабатывать под
конкретных заказчиков (embedded/white-label) — отсюда требование к Docker и
к точкам интеграции с внешними системами (не реализуются сейчас, но
закладываются как расширяемые места — например, интерфейс/порт для будущей
синхронизации остатков или приёма заказов из внешней учётной системы).

## 2. Основные сущности (черновик)

- `Product` — артикул (SKU), название, описание, категория, единица измерения
  (шт/метр/кг), фото/видео, текущий остаток, цена (для демо — опционально).
- `StockMovement` — журнал изменений остатка (причина: приход, резерв,
  отмена резерва, продажа, ручная корректировка) — нужен для аудита и
  чтобы остаток всегда был производным/проверяемым значением.
- `Reservation` — резерв товара пользователем: количество, статус
  (active/cancelled/fulfilled/expired), TTL резерва (сколько держим бронь).
- `Order` / `Purchase` — подтверждённый администратором выкуп резерва.
- `User` — покупатель (аутентификация — TBD, скорее всего просто
  телефон/email + OTP для демо).
- `Admin` — сотрудник магазина, роль.
- `QrCode` — привязан к `Product` (для склада/печати) и к `Reservation`/`Order`
  (для покупателя, чтобы предъявить на выдаче).

## 3. QR-коды

- Для товара: короткий код на основе артикула (SKU) — QR должен быть
  маленьким/плотным, чтобы нормально печататься на принтере этикеток.
  → используем короткий алфавит (base32/base62) и короткую полезную нагрузку,
  не URL целиком, а короткий id, который резолвится на сервере/в приложении.
- Для заказа/резерва: QR на основе случайного id (не последовательного,
  чтобы нельзя было подобрать чужой резерв).
- Библиотеки: генерация — zxing (JVM/Android) или qrcode (backend, любой
  стек); сканирование — вопрос стека мобильного приложения (см. §5).

## 4. Нефункциональные требования

- Тесты (unit + минимум e2e на ключевые сценарии: резерв → подтверждение →
  списание остатка).
- Аналитика и стабильность (crash reporting) — приоритет: бесплатные тарифы
  на малых объёмах. Кандидаты: Sentry (free tier, backend + mobile),
  PostHog (free tier, продуктовая аналитика), Firebase Crashlytics
  (для мобилы, если стек это позволяет).
- Docker/Docker Compose — обязательно, т.к. предполагается клонирование
  "коробки" под заказчиков.
- Точки интеграции с внешними системами — закладываем интерфейсы
  (например, порт для будущего адаптера остатков/заказов), саму интеграцию
  не реализуем.

## 5. Стек (подтверждён, версии зафиксированы 2026-09-12)

- Мобила/веб: Kotlin Multiplatform (KMP) + Compose Multiplatform (CMP) —
  Android/iOS(arm64 + simulator arm64)/Desktop/Web(Wasm) из одной кодовой
  базы.
- Backend: Kotlin + Ktor (Netty), Exposed + PostgreSQL JDBC driver.
- Версии на момент сборки скелета (проверены по официальным
  release-страницам, не по памяти модели — см. коммит со скелетом):
  Kotlin 2.4.20, Ktor 3.5.2, Compose Multiplatform 1.12.0, AGP 9.3.0,
  Gradle 9.7.1, kotlinx.coroutines/serialization 1.11.0, Exposed 1.5.0.
  Целиком в `gradle/libs.versions.toml`.
- Хостинг демо: **Contabo Cloud VPS 4** (4 vCPU/8 GB/100 GB SSD, €5.24/мес)
  — инстанс создан и SSH-доступ подтверждён 2026-09-15, см.
  `docs/hosting-contabo.md`. Сравнение вариантов и более ранняя попытка на
  Oracle Cloud Always Free — см. §5.1 и `docs/hosting-oracle-free-tier.md`
  (историческая, для сравнения; статус самого Oracle-инстанса, если он
  ещё существует, не проверялся после перехода на Contabo).

   (KMP/CMP: Android/iOS/Web).
4. Демо знакомым → доработка по фидбеку → подготовка к выходу на рынок.

## 5.1 Хостинг демо — сравнение вариантов (перепроверено 2026-09-12)

Пользователь попросил перепроверить актуальные бесплатные/дешёвые VPS
после того, как реальный лимит Oracle оказался ниже, чем в первой версии
этого раздела. Ниже — то, что подтвердилось с официальных страниц
провайдеров (не только по агрегаторам/памяти), с датой проверки:

| Вариант | Ресурсы | Цена | Проверено |
|---|---|---|---|
| **Oracle Cloud Always Free** (Ampere A1, ARM) | **2 OCPU / 12 GB RAM** суммарно на весь аккаунт (можно одним инстансом или разбить) + до 200 GB диска | €0 навсегда | ✅ officially: [docs.oracle.com Always Free Resources](https://docs.oracle.com/en-us/iaas/Content/FreeTier/freetier_topic-Always_Free_Resources.htm) — лимит урезан с 4/24 до 2/12, вступило в силу 15.06.2026 |
| **Google Cloud Always Free** (`e2-micro`) | 2 vCPU (shared/burstable, реально доступно немного), 1 GB RAM, 30 GB диска | €0 навсегда, но **только в регионах US** (us-west1/us-central1/us-east1) — заметный пинг из СНГ | ✅ official: [Google Cloud Free features](https://docs.cloud.google.com/free/docs/free-cloud-features) |
| **Hetzner CX22** | 2 vCPU, 4 GB RAM, 40 GB SSD, x86_64 | ~€4.35/мес (≈$4.59) | ⚠️ подтверждено несколькими независимыми обзорами 2026 года (betterstack, vpsfor.dev, bestusavps), официальную страницу с ценами не удалось получить напрямую (рендерится через JS) — проверить точную цифру на hetzner.com в момент регистрации |
| **Contabo Cloud VPS 4** | 4 vCPU, 8 GB RAM, 100 GB SSD | €5.50/мес (тариф на 24 месяца — при более коротком сроке дороже) | ✅ official: [contabo.com/en/vps](https://contabo.com/en/vps/) |

**Рекомендация не изменилась, но теперь обоснована точнее:**

- **Если оставаться на бесплатном** — Oracle всё ещё лучше GCP для этой
  задачи: 2 OCPU/12 GB против 1 GB RAM у GCP, и сервер физически можно
  разместить не только в США (меньше пинг). GCP e2-micro имеет смысл
  только как второй бесплатный сервер про запас (например для staging),
  не как замена Oracle.
- **Если готовы платить немного** — между Hetzner CX22 (2 vCPU/4 GB,
  €4.35) и Contabo Cloud VPS 4 (4 vCPU/8 GB, €5.50) при близкой цене
  **Contabo даёт вдвое больше ресурсов**, но Hetzner исторически надёжнее
  по сети/поддержке и проще уезжает на k3s/managed-балансировщик, когда
  дело дойдёт до масштабирования — платишь чуть больше за предсказуемость.
  Для демо на знакомых это не критично — оба варианта работают, выбор
  скорее between "больше ресурсов сейчас" (Contabo) и "меньше сюрпризов
  позже" (Hetzner).
- Если Oracle снова даёт только 1 OCPU/6 GB при создании инстанса —
  вероятно, дефолт слайдера в форме создания, а не фактический лимит:
  официальный лимит аккаунта — 2 OCPU/12 GB, попробуй руками подвинуть
  ползунок Ampere A1 до максимума при создании/редактировании shape.

## 8. Стартовый скелет (реализовано 2026-09-12)

Собран и **реально собирается и проходит тесты** (не только написан "на
глаз") — проверялось прогоном `./gradlew` локально с JDK 21
(`Android Studio\jbr`) и Android SDK, а не только чтением документации.

Структура:

```
server/       — Ktor backend (JVM). /health роут + заглушка.
shared/       — KMP: общие модели/логика (пока только заглушка Greeting).
composeApp/   — KMP + Compose Multiplatform UI (общий код для всех клиентов).
androidApp/   — точка входа Android-приложения (ОБЯЗАТЕЛЬНО отдельный
                модуль начиная с AGP 9 — см. ниже).
```

Проверено сборкой: `:shared:jvmTest`, `:server:test` (health-check отвечает
200 OK), `:composeApp:desktopTest`/desktop-таргет компилируется,
`:androidApp:assembleDebug` (APK собирается). iOS/Wasm таргеты объявлены в
Gradle, но не прогонялись (нет Mac; Node/Yarn для wasmJs не гонял) — по
конфигурации не должны требовать доработок, но не проверены живым запуском.

**Важный нюанс, на который наткнулись при сборке (не тривиально из
документации на первый взгляд)**: начиная с **AGP 9.0** плагин Kotlin
Multiplatform несовместим с `com.android.application`/`com.android.library`
напрямую. Поэтому:
- `shared` и `composeApp` используют новый плагин
  `com.android.kotlin.multiplatform.library` и блок `kotlin { android { ... } }`
  (не `com.android.library` + отдельный `android { }` блок, как было раньше).
- Реальное Android-приложение (Activity, манифест) обязано жить в **отдельном**
  модуле (`androidApp`), который уже использует обычный
  `com.android.application` и просто зависит от `composeApp`.
- `compose.runtime`/`compose.foundation`/`compose.material3`/`compose.ui`
  через `compose.*` accessors в Gradle-плагине помечены deprecated, но их
  ручная замена на явные Maven-координаты — ловушка: у `material3` версии
  артефакта **не совпадают** с версией плагина Compose Multiplatform
  (последняя стабильная `material3` — 1.9.0, а не 1.12.0) — accessors это
  скрывают за собой, поэтому в скелете сознательно оставлены deprecated
  accessors (`compose.runtime` и т.д.) с `@Suppress("DEPRECATION")` вместо
  угадывания версий вручную.
- `iosX64` (Intel-симулятор) исключён из таргетов — Compose Multiplatform
  1.12.0 для него не публикуется, только `iosArm64`/`iosSimulatorArm64`
  (актуально для любого современного Mac на Apple Silicon).
- `compileSdk`/`targetSdk` — 37, не 36: androidx.compose 1.12.0 требует
  compileSdk ≥ 37 (AAR metadata check не даёт собраться на 36).

CI (`.github/workflows/ci.yml`) пока гоняет только JVM-таргеты
(`shared:jvmTest`, `server:test`, `composeApp:desktopTest`) — Android
(нужен SDK) и iOS (нужен macOS-раннер) добавим отдельно, когда понадобится.

Реальных доменных фич/моделей ещё нет — по договорённости с пользователем
("до кода — сетап, заглушки, потом детальное обсуждение архитектуры фич")
это сознательно только рабочий каркас.

## 9. Организация агентов (после решения открытых вопросов)

- **Сбор требований** — агент/сессия, уточняющая детали фич и пишущая
  спецификации по каждой фиче в `docs/features/*.md`.
- **Кодеры** — по фичам/слоям (backend API, KMP shared, Android/iOS/Web UI).
- **Верификация** — ревью кода + прогон тестов перед мержем, отдельная
  роль/агент, не совпадающая с автором фичи.
